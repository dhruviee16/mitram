# design-sync notes

## Repo shape

mitram is an app, not a component-library package. `src/components/ui/` holds 20 shadcn (base-nova / Base UI) components, no prior dist build, no Storybook. To satisfy design-sync's package shape:

- Added `src/components/ui/index.ts` — hand-written barrel `export *`ing all 20 files. Keep it in sync when adding/removing files under `src/components/ui/`.
- Added `tsup.config.ts` + `tsconfig.ds.json` (extends the app tsconfig with `incremental: false` — tsup's dts build errors on `--incremental` unless a `tsBuildInfoFile` is set) + `package.json` script `build:ds` → outputs `dist-ds/index.mjs` + `.d.mts`.
- Set root `package.json` `"types": "dist-ds/index.d.mts"` so the converter's `findTypesRoot`/`loadDts` can find it (it only recognizes `.d.ts` by extension in its directory-scan heuristic, but honors `pkgJson.types` verbatim, `.d.mts` included).
- CSS: app uses Tailwind v4 CSS-first (`@import "tailwindcss"` in `src/app/globals.css`, no static utility classes on disk). `buildCmd` compiles a real stylesheet with `@tailwindcss/cli`, scoped to `src/components/ui/**` content, into `dist-ds/styles.css` — this is `cfg.cssEntry`.
- 82 components discovered (20 top-level + subcomponents: CardHeader, DialogContent, SelectItem, etc. — all separate PascalCase exports from the barrel). Discovery grouped everything under a single `general` group — no per-component regrouping was done this run.

## Re-sync risks

- `build:ds` isn't part of the app's normal `pnpm build`/CI — it's design-sync-only. If `src/components/ui/*.tsx` changes without re-running `pnpm build:ds` + the CSS compile, `_ds_sync.json` will describe stale output. Always run `cfg.buildCmd` before re-syncing.
- The barrel `index.ts` is hand-maintained — adding a new `src/components/ui/<name>.tsx` file needs a matching `export * from "./<name>"` line or the converter won't see it.
- `dist-ds/` and the Tailwind-CLI-compiled `styles.css` are build artifacts (gitignored) — never committed, always regenerated by `buildCmd`.
- Font gap above is a real open risk, not just noise — flag to the user before calling this "done."
